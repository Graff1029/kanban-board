## Быстрый старт

### Windows

1. Установите Python 3.12, если его нет.
2. Распакуйте архив и откройте папку `kanban`.
3. Запустите `start.bat`. При первом запуске нужен интернет — скачиваются библиотеки.
4. Дождитесь сообщения `Uvicorn running` и откройте http://127.0.0.1:8000.
5. Зарегистрируйтесь. **Первый зарегистрированный пользователь становится администратором**, остальные — разработчиками.

Окно сервера оставьте открытым. Чтобы остановить сервер, нажмите `Ctrl+C`.

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

### Важно знать

- Данные хранятся в папке `data`, она создаётся при первом запуске. Готовых аккаунтов и паролей в архиве нет.
- Роль менеджера назначает администратор через кнопку «Участники».
- Открытие `index.html` двойным щелчком не заменяет сервер: вход, база и сохранение задач работают через Python.

## Возможности

- **Проекты и доски** — создание, изменение, удаление.
- **Колонки** — создание, переименование, порядок стрелками, WIP-лимит (0 — без лимита). Непустую колонку нужно сначала освободить.
- **Задачи** — создание, изменение, удаление, перенос мышью или выбором колонки в форме.
- **Поля задачи** — название, описание, исполнитель, приоритет, срок, метки (через запятую).
- **Комментарии, история изменений, вложения** — файлы TXT, PDF, PNG, JPG до 5 МБ.
- **Поиск и фильтры** — поиск по названию и описанию, фильтры по исполнителю, приоритету и точной метке.

Дополнительно:

- На странице выводится до 200 карточек, остальные открываются кнопками «Назад» и «Дальше». Счётчик колонки учитывает все её задачи, в том числе скрытые фильтром или другой страницей.
- На телефоне колонки прокручиваются внутри доски.
- Все зарегистрированные участники работают с общими проектами.

**Не реализовано:** email-уведомления, WebSocket и восстановление пароля (оно есть только как пример тест-кейса).

## Роли и права

| Роль | Что может |
| --- | --- |
| Администратор | Всё, что менеджер, плюс назначение ролей |
| Менеджер | Проекты, доски, колонки и задачи |
| Разработчик | Задачи, комментарии и вложения |

- Права проверяет сервер при каждом запросе; скрытие кнопок в браузере нужно только для удобства.
- После смены роли нужно войти заново, чтобы обновились кнопки. API применяет новые права сразу.
- Своё вложение может удалить любой пользователь, чужое — менеджер или администратор.
- JWT хранится в памяти вкладки и действует 8 часов. После обновления страницы нужно войти снова. Кнопка выхода отзывает сеанс на сервере.

## Технологии и архитектура

| Часть | Технология | Почему |
| --- | --- | --- |
| Сервер и API | Python, FastAPI | Сам проверяет входные поля и создаёт Swagger |
| База данных | SQLite | Не требует отдельного сервера |
| Интерфейс | HTML, CSS, JavaScript | Не нужен сборщик |
| Тесты | Pytest, Playwright | API-тесты и проверка действий в браузере |

Альтернативы: React + Express + PostgreSQL потребовали бы больше настройки; во Flask документацию API и проверку полей пришлось бы подключать отдельно.

**Как работает приложение.** Это небольшой монолит из трёх слоёв:

```
Браузер ──fetch──▶ app.py ──▶ services.py ──▶ db.py ──▶ SQLite
                  запросы      правила         соединение
                  и поля       и права         и транзакции
```

Значения в SQL передаются через `?`.

**Данные.** Проект содержит доски, доска — колонки, колонка — задачи. Комментарии, история и вложения связаны с задачей. Внешние ключи обеспечивают каскадное удаление.

**Миграции.** Первая схема лежит в строке `SCHEMA` в `db.py`, её номер хранится в `PRAGMA user_version`; при повторном запуске таблицы не пересоздаются. Любое изменение схемы для уже созданной базы делается новой миграцией в `db.py`, а не правкой первой.

## API

Интерактивная документация: http://127.0.0.1:8000/docs (Swagger), схема: http://127.0.0.1:8000/openapi.json. Swagger загружает оформление с CDN, поэтому ему нужен интернет; сам интерфейс доски работает только на локальных файлах.

После входа JWT передаётся в заголовке `Authorization: Bearer ТОКЕН`. В Swagger его можно вставить через кнопку Authorize.

| Действие | Запрос |
| --- | --- |
| Регистрация, вход, выход | `POST /api/register`, `/api/login`, `/api/logout` |
| Текущий пользователь, список участников | `GET /api/me`, `/api/users` |
| Назначить роль | `PATCH /api/users/{id}/role` |
| Проекты | `GET/POST /api/projects`, `PUT/DELETE /api/projects/{id}` |
| Доски проекта | `GET /api/projects/{id}/boards` |
| Создать, изменить, удалить доску | `POST /api/boards`, `PUT/DELETE /api/boards/{id}` |
| Состояние доски и фильтры | `GET /api/boards/{id}?q=&label=&priority=&assignee_id=&limit=200&offset=0` |
| Колонки | `POST /api/columns`, `PUT/DELETE /api/columns/{id}` |
| Порядок колонок | `PUT /api/boards/{id}/order`, тело `{"ids":[3,1,2]}` |
| Задачи | `POST /api/tasks`, `GET/PUT/DELETE /api/tasks/{id}` |
| Комментарий | `POST /api/tasks/{id}/comments` |
| Вложения | `POST /api/tasks/{id}/attachments`, `GET/DELETE /api/attachments/{id}` |

`PUT` принимает все поля редактируемого объекта.

**Коды ответов:**

| Код | Значение |
| --- | --- |
| 401 | Нужен вход |
| 403 | Нет прав |
| 404 | Запись не найдена |
| 409 | Конфликт или превышен WIP |
| 413 | Файл слишком большой |
| 422 | Неверные поля |

## Как запустить тесты

Команды выполняются в папке `kanban`. Примеры для Windows.

### 1. Установка библиотек для тестов

```bat
.venv\Scripts\python -m pip install pytest==9.1.1 pytest-cov==7.1.0 httpx==0.28.1 playwright==1.51.0 ruff==0.17.1 locust==2.46.7 pip-audit==2.10.1
```

### 2. Линтер и модульные/API-тесты

```bat
.venv\Scripts\python -m ruff check --isolated --select E4,E7,E9,F .
.venv\Scripts\python -m pytest tests/test_api.py --cov=app --cov=services --cov=db --cov-branch --cov-fail-under=80 --cov-report=term-missing
```

Тесты работают на временных базах и не трогают рабочие данные. Покрытие считается только для трёх серверных файлов, JavaScript не входит. В CI дополнительно проверяется порог покрытия ветвей 70%.

### 3. Браузерный тест (E2E)

Тест сам запускает временный сервер.

```bat
.venv\Scripts\python -m playwright install chromium firefox msedge
set E2E_BROWSERS=chromium,firefox,msedge
.venv\Scripts\python tests/e2e.py
```

Без переменной `E2E_BROWSERS` запускается Chromium; для установленного Google Chrome укажите `chrome`. Результаты и трассы сохраняются в `reports`.

### 4. Проверка зависимостей

```bat
.venv\Scripts\python -m pip_audit -r requirements.txt
```

### 5. Нагрузочный тест

Используйте отдельную пустую базу. В первом терминале:

```bat
set DB_PATH=data\load.db
.venv\Scripts\python tests/load.py
.venv\Scripts\python -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Во втором терминале, в той же папке:

```bat
.venv\Scripts\python -m locust -f tests/load.py --headless --host http://127.0.0.1:8000 -u 1000 -r 100 --run-time 60s --csv reports/load --html reports/load.html --stop-timeout 10
```

Подготовка создаёт 10 000 задач, 1000 пользователей и отдельные JWT на сутки. Команда откажется менять базу, где уже есть пользователи. Токены в `reports/load-tokens.json` нельзя публиковать. Между действиями пользователей пауза 1–3 секунды, поэтому 1000 пользователей — это не 1000 запросов в секунду.

### План

- **Цель:** проверить обычные действия, ошибки ввода, права, целостность базы, интерфейс и поведение под нагрузкой.
- **Окружение:** Linux, Python 3.12, SQLite.
- **Этапы:** анализ требований, реализация, модульные и API-проверки, браузерный сценарий, нагрузка, проверка безопасности.
- **Критерий начала:** приложение запускается, миграция создаёт базу, открывается страница.
- **Критерий завершения функциональной части:** автотесты проходят, права и WIP проверяются сервером, данные сохраняются.
- **Риски:** ограниченные ресурсы компьютера, установка браузеров, отсутствие внешнего сервера.

### Модульные, API и браузерные тесты

- Выполнено **30 проверок**: 5 модульных и 25 API/интеграционных. Все прошли.
- Покрытие серверных строк и ветвей — **100%**.
- Pytest выводит предупреждение Starlette об устаревающем использовании HTTPX в `TestClient`. Оно не скрыто и не влияет на результат.
- Браузерный сценарий проверен в **Chromium 134** и **Firefox 135**. В изолированной среде Firefox запускался с отключённым sandbox — только для этого тестового запуска, в код приложения такие настройки не добавлялись.
- **Не проверено:** Microsoft Edge (не удалось установить в среде) и отдельный Google Chrome.

### Нагрузочный тест

Параметры: 1000 пользователей, рост по 100 в секунду, 60 секунд, ожидание завершения 10 секунд. Данных не меньше 10 000 задач. Сервер (один процесс Uvicorn) и генератор нагрузки работали на одной машине. Замер сделан до объединения файлов; правила API с тех пор не менялись.

| Метрика завершённых запросов | Значение |
| --- | --- |
| Количество | 4250 |
| HTTP-ошибки | 0 |
| Средний отклик | ≈ 13 022 мс |
| Медиана | ≈ 14 000 мс |
| p95 | ≈ 18 000 мс |
| Максимум | ≈ 21 167 мс |
| Средняя интенсивность | ≈ 60,81 запроса/с |

Выводы:

- Требование «отклик < 200 мс» **не выполнено**, 1000 запросов в секунду не достигнуты.
- Часть действий не успела завершиться до остановки, поэтому «0 HTTP-ошибок» не означает отсутствия проблем.
- В среде замера не удалось собрать метрики CPU (`psutil` не видел PID процесса); сбор CPU был отключён только во внешнем запуске, на HTTP-измерения это не влияет. В проект включён обычный сценарий без этого обхода.
- Результаты не заменяют повторный замер на другом компьютере.

## Безопасность и ограничения

**Что сделано:**

- Пароли хешируются bcrypt.
- JWT проверяется по подписи, сроку действия и сеансу в базе.
- Сервер проверяет роли, размер и тип вложений.
- Пользовательский текст выводится через `textContent`, SQL использует параметры.
- Авторизация не использует cookie, CORS не включён.
- Заголовки CSP, `nosniff` и запрет iframe задаёт сервер.
- Проверка зависимостей `pip-audit` от 19 октября 2026 года не нашла известных уязвимостей в серверных библиотеках.

**Чего нет:**

- HTTPS и HSTS — требуют отдельного развёртывания.
- Антивирусная проверка вложений, ограничение попыток входа по IP, длительный мониторинг.
- Измерение доступности 99,9%.
- Docker и конфигурации публичного хостинга.

`pip-audit` — это не полный аудит безопасности.

## CI/CD и деплой

Файл `.github/workflows/check.yml` запускается при push и pull request. Он выполняет lint, unit-тесты, проверку сборки Python, integration/API-тесты, E2E, `pip-audit` и ZAP, затем сохраняет отчёты и архив.

- Чтобы CI заработал, загрузите содержимое папки `kanban` в корень GitHub-репозитория.
- Для приватного Codecov может понадобиться секрет `CODECOV_TOKEN`.
- ZAP baseline пассивно проверяет только страницы, доступные без входа. Это не заменяет активное сканирование API под разными ролями.
- Внешний workflow, ZAP и деплой пока не запускались. Локальный запуск не требует GitHub и Linux-сервера.

### Деплой по push в `main`

Предусмотрен, но **отключён** до настройки.

**Что нужно настроить на GitHub:**

- переменная репозитория `DEPLOY_ENABLED=true`;
- environments `staging` и `production`;
- в каждом из них секреты `DEPLOY_HOST`, `DEPLOY_USER`, `DEPLOY_KEY`, `KNOWN_HOSTS`.

**Что нужно подготовить на каждом сервере:**

1. Установить Python и разместить проект в `~/kanban`.
2. Создать окружение: `python3 -m venv ~/kanban/.venv`.
3. Сохранить пользовательский сервис в `~/.config/systemd/user/kanban.service`:

   ```ini
   [Unit]
   Description=Kanban
   [Service]
   WorkingDirectory=%h/kanban
   ExecStart=%h/kanban/.venv/bin/uvicorn app:app --host 127.0.0.1 --port 8000
   Restart=on-failure
   [Install]
   WantedBy=default.target
   ```

4. Установить библиотеки: `~/kanban/.venv/bin/pip install -r ~/kanban/requirements.txt`.
5. Включить сервис:

   ```bash
   systemctl --user daemon-reload
   systemctl --user enable --now kanban
   ```

6. Чтобы сервис работал после выхода пользователя, администратор сервера должен включить linger.
7. HTTPS настраивается отдельно через обратный прокси с сертификатом.

Наличие workflow и `Restart=on-failure` не подтверждает ни работающий внешний деплой, ни доступность 99,9%.
